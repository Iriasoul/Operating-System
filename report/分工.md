### 1.3 接口约定与协作顺序

1. **共同确认接口。** 开发前一起核对 `SAVE_ALL`、`struct trapframe`、`trap()`、`trap_dispatch()` 和已有测试程序，明确 Trap frame 的布局及汇编与 C 之间的调用关系。不修改指导书要求保持不变的结构体、函数签名和既有保存逻辑。
2. **分别完成实现。** 石晨昊负责 `trapentry.S`；王策和吕昊远分别负责 `trap.c` 中的 `interrupt_handler()` 与 `exception_handler()`。两人在同一文件中开发时仅修改各自函数，合并时共同核对，避免覆盖对方代码。
3. **先验证入口与返回。** 石晨昊和吕昊远联合检查断点触发、寄存器恢复和 EPC 更新，确认 Trap 可以正确进入 C 处理函数并返回。
4. **再验证持续中断。** 王策负责时钟专项验证，吕昊远协助整体验证；核对持续触发、输出次数、计数与关机行为，石晨昊协助排查上下文恢复问题。
5. **交叉复核并汇总。** 石晨昊复核中断处理，王策复核异常处理，吕昊远复核汇编入口与恢复；三人共同确认指导书要求、代码、提示词和报告描述一致。
